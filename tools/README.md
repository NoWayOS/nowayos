# tools: the make targets in detail

`make` (the help) lists every target. This page says what each does in full.

## Targets

| Command | Where | What |
| --- | --- | --- |
| `make test` | container (`IN=host`: host) | unit, property, doc and golden-image tests |
| `make demo` | container (`IN=host`: host) | the demo's scripted session (`crates/nowayos-demo`), every frame checked against `session/*.png` (`NOWAYOS_UPDATE_SNAPSHOTS=1` rewrites them) |
| `make atlases` | container (`IN=host`: host) | the glyph atlases made again from the pinned font (`tools/glyph-atlas`, a workspace of its own) into `crates/nowayos-glyphs/src/atlas/`: a generated Rust module and coverage file per face and size, `mod.rs` and `manifest.toml`. Refuses, writing nothing, a file that differs from its pin in `glyphs.toml`, a file in `fonts/` that is not pinned, or a character of the set the font lacks. Then the icons' alpha masks (`tools/icon-masks`, Python) from the Lucide SVG files `crates/nowayos-icons/icons.toml` pins into `crates/nowayos-icons/src/masks/`: a coverage file per icon and scale, and `mod.rs`; it refuses a file that differs from its pin, an SVG file not named, or a fill, transform, stroke width or element it does not draw. The same bytes on the host and in the container; review the change and commit it |
| `make atlases-check` | container | the atlas tool's rustfmt, clippy and tests; the atlases made again into `build/atlases/` and compared with the checked-in ones, file by file; then `cargo tree` of the root, `pds/` and `fuzz/` workspaces, which must hold none of the rasteriser's crates (`RASTERISER_CRATES`; `tools/check-crates-absent`, which also fails a tree it cannot read: cargo tree failing, or listing no crate); then the icons' masks drawn again into `build/icon-masks/` and compared |
| `make lint` | container (`IN=host`: host) | `cargo fmt --check`, then clippy with `-D warnings` |
| `make fmt` / `make doc` | container (`IN=host`: host) | format / build docs with warnings as errors |
| `make clean` | container (`IN=host`: host) | remove that environment's target directory |
| `make container` | host | build the dev image `nowayos-dev:0.1` (again after Containerfile changes) |
| `make shell` | container | an interactive shell in the dev container, the workspace at `/work` |
| `make sdk-boards` | container | the boards and configurations in the pinned Microkit SDK |
| `make system-clean` | container | remove `build/`, the PDs' build output and U-Boot's tree |
| `make nostd` | container | build every crate except `HOST_ONLY_CRATES` (the Makefile) for `aarch64-unknown-none` |
| `make deny` / `make pds-deny` | container | the baseline check of all four workspaces (`deny` only), then cargo-deny: licences, sources, bans, advisories (`deny`: the root, `fuzz/` and `tools/glyph-atlas/` workspaces; `pds-deny`: `pds/`); the bans include smoltcp's exact feature set (`[[bans.features]]`) |
| `make sbom` | container | a CycloneDX 1.5 SBOM per workspace in `build/sbom/` (`tools/sbom`, our own; the same rule in every repo: what the product is built from is `required`, dev-dependencies, build-time tools, host-only crates and other platforms' dependencies `excluded` with the reason; the PDs' also lists `core`, `alloc` and `compiler_builtins`; everything in the fuzz harness's is `excluded`, a test harness; the atlas tool's runs on the build host only) |
| `make secrets` | container (no network) | the tree, and every version of every file and every commit message on every ref, scanned for keys and credentials (`tools/secrets-scan`, our own; every repo runs it): a finding names its file and line and a fingerprint, never the text; reviewed false positives in `secrets-allow.toml`, one exact entry each with its reason; a shallow clone fails |
| `make publication-scan TERMS=FILE` | container (no network) | for the maintainers, before the open repositories are published: their trees, every version of every file, every commit message, identity, ref and tag, for the terms in FILE - a list kept outside every repository, in the workspace folder - and for links into Azure DevOps, assistant instruction files (`CLAUDE.md`), wiki references and every identity (`tools/publication-scan`). A finding names a term by its line in FILE, never its text, so the report can go into a work item or page. Not in `make ci` |
| `make fuzz` | container | the fuzz harness (`fuzz/`, its own workspace): rustfmt and clippy, then each target in `fuzz/fuzz_targets/` built with libFuzzer's instrumentation (cargo-fuzz's flags, on the stable toolchain) and run for `FUZZ_SECONDS` (10) seconds - `nowayos-ipc`'s decoders and its ring consumer over memory a hostile producer changes, `nowayos-input`'s events, the virtio-input path through the broker and a terminal's bytes through the terminal decoder and the broker (`input_terminal`), `nowayos-time`'s records - as bytes, and as the message registers a reading crosses a call in - and the clock's checks on the samples that decode, `nowayos-update`'s trust list, update manifest and bundle chunks, `nowayos-signature`'s P-256 check, the socket records with both sides' connection tables (`nowayos-socket`), the seed record taken off a seed ring (`nowayos-seed`), `nowayos-net`'s queues - each end over memory a hostile peer writes, every descriptor taken checked with `DataRegion` - and its ARP parser (`net_queue`, `net_arp`), and the network stack's receive path - frames and descriptors from a hostile driver through `nowayos-ip`'s checks and copy into smoltcp's parsing and DHCP client, and `nowayos-usb`'s decoders of what an xHCI controller and a USB device write - event records, capability registers, port status (`usb_xhci_records`), descriptors and an enumeration fed any answers, a boot keyboard or mouse never crowded out by another HID interface, and audio streaming interfaces' isochronous endpoints, PCM formats, rates and feedback endpoints, an enumeration that streams and sets rates among them (`usb_descriptors`), the audio channel's records and a lossy ring a hostile producer writes (`audio_records`), a camera's configuration walked for its Motion JPEG sizes, rates and settings, its answer to the probe, its payload transfers assembled into whole frames, the frame ring's records and counts, and an enumeration that looks for a camera (`usb_video`), and HID boot reports turned into events, a keyboard's keys and a mouse's buttons never left down and its pointer on the screen (`usb_hid_reports`), and HID report descriptors - a touchscreen's, a tablet's or a ten-contact screen's - walked within their bounds, each report's length recorded, and their reports turned into touches and pointer moves (`usb_report_descriptors`). Corpus and crashes in `build/fuzz/`; `FUZZ_TARGETS=NAME` runs one, `FUZZ_INPUT=FILE` runs one target on one input |
| `make tools-test` | container | tests for `tools/` |
| `make update-bundles` | container | throwaway test keys and the signed records the update tests read (`tools/update-bundles`): the dev image's openssl makes root, image, configuration and stranger key pairs in the container's `/tmp`, deleted when the run ends - no private key ever reaches the workspace - and writes only public keys and signed records to `build/update-bundles/`: the root key as the trust anchor, trust lists v0 to v2, an image, and bundles of chunk records, one accepted and one for each refusal the update PD must give (`bundles.json` names each). OpenSSL signs and RustCrypto verifies: nowayos-update's `openssl_bundles` test runs the tool and reads every record back |
| `make unsafe-audit` | container | `unsafe` only in the approved crates, and getrandom's back end - `register_custom_getrandom!`, `__getrandom_custom`, `__getrandom_v03_custom` - named in no source outside `nowayos-entropy` |
| `make forget-verdicts` | container | delete the cached verdicts of Kani, Miri and fuzzing (`CI_VERDICTS`), so the next `make ci` runs every one a change reaches |
| `make sel4-config-check` | container | the seL4 verification position (`tools/sel4-verification.toml`) is for the Microkit SDK the Containerfile pins |
| `make image-sbom SYSTEM=hello` | container | `make image`, which also writes the image's CycloneDX 1.5 SBOM beside `loader.img` (`build/BOARD/SYSTEM/sbom.cdx.json`; `tools/image-sbom`): the SDK's kernel, loader, monitor and capDL initialiser, every program image and each crate compiled into it (cargo's unit graph for the same build, the std crates included), the system description and prefill files, each with its sha256, and the image's own; for `rpi5b_2gb` also U-Boot, the firmware and `config.txt` (`make sdcard` adds `u-boot.bin`'s sha256). Licences and audit status of the SDK and boot files are in `tools/image-components.toml`, reviewed: a GPL part is marked as needing a source offer; the capDL initialiser holds, as nested components, the 41 crates its audit found (`tools/initialiser-audit.toml`), marked 'audited' (its one licence off the house list signed off), or 'audited, sign-off pending' while a licence in it awaits the project owner, and 'composition unaudited' again under any SDK but the one audited; a new SDK or firmware file fails until it is listed there. `make image` puts the glyph atlases' notice (`OFL.txt`) and the icons' (`LICENSE-LUCIDE.txt`, Lucide's ISC licence; the SBOM names `nowayos-icons` with it in an image that links an icon) beside every image, which the SBOM lists with the font the atlases were made from (`crates/nowayos-glyphs/src/atlas/manifest.toml`), as it names that font on the atlas crate's component in an image that links it |
| `make pds-lint` / `make pds-test` | container | rustfmt and clippy / tests for the `pds/` workspace; clippy lints each PD with a heap (`PDS_LINT_ALONE`) on its own, so that its dependencies' features - rustls's `zeroize` with `alloc` - never reach the PDs without one |
| `make pds-miri` | container | Miri over the approved-unsafe `pds/` crates, each crate its own run, side by side (logs in `build/miri/`). The everyday gate checks aliasing under Tree Borrows; the checkpoint gate - `make ci CI_SCOPE=full` and `make release-evidence` - under Stacked Borrows, Miri's default and the stricter, which takes `nowayos-region` about 8 minutes. `MIRI_MODEL=stacked` or `tree` chooses either for any run |
| `make qemu-test SYSTEM=hello` | container | build, check grants, boot headless, check output (`ipc-demo`, `isolation-test`, `pl011-demo`, `dma-demo`, `timer-demo`, `restart-test`, `display-test`, `virtio-input-test`, `input-broker-test`, `input-isolation`, `net-test`, `net-isolation`, `net-stack-test`, `net-stack-no-seed`, `net-stack-bad-frames`, `virtio-console-test`, `clock-test`, `signature-test`, `usb-test`, `usb-input-test`, `usb-audio-test`, `supervisor-test`, `supervisor-panic`, `supervisor-counts`, the six `failsafe-*`, `supervisor-empty-list`, `supervisor-bad-list`, `supervisor-failsafe-release`, `ui-demo`, `ui-interactive`, `ui-isolation`, `ui-isolation-widened`, `uart-input-test`, `update-test`, `budget-test`, `budget-test-widened`, `getrandom-test` too; `make qemu-test-all` boots a system in each configuration its `systems/NAME.configs` lists, and again at each line rate its `systems/NAME.baud` lists); `QEMU_BAUD=115200` takes QEMU's serial no faster than the Pi 5's UART, where a line takes up to 8 ms and two PDs printing at once mix their lines (`pds/README.md`, "When several PDs print"); a system with a display device in `systems/NAME.qemu` also has its screen compared with `systems/NAME.screen.png` (`NOWAYOS_UPDATE_SNAPSHOTS=1` rewrites it; review it by eye), and `systems/NAME.qmp` drives QEMU over QMP (keys, clicks, pauses) as serial lines appear, and can compare the screen with an approved image at any step |
| `make qemu-test-all` | container | every system; for each with a `systems/NAME.reproducible` file, `make image-reproducible`; a system with a `systems/NAME.harness` file is booted only by the make target that file names, run once (`update-trial-test`) |
| `make update-trial-test` | container | the update tests across reboots (`tools/update-trial`): makes the run's keys, builds `update-trial-r1` and `-r2` with them, signs a bundle of release 2's whole image and deletes the keys; then plays the device - its storage, both copies of the update state and what each slot holds, and its bootloader, which boots the slot the state names and a slot marked for a trial once - across nine QEMU runs (`-no-reboot`): the staging run, then a trial whose health check passes, fails, comes late or faults, and the run after each. Each run's disk goes to QEMU by fw_cfg, its state comes back in its serial log, and its output is checked against `systems/update-trial/RUN.expect`; logs in `build/update-trial/`. `UPDATE_TRIAL_TIMEOUT` (120 s) a run |
| `make image-reproducible SYSTEM=NAME` | container | the same inputs give the same image: SYSTEM's image built, set aside, its build removed and built again, the two compared byte for byte - with the update tests' keys and bundles kept between the two (`UPDATE_BUNDLES_KEEP=1`). A system that prefills `test-trust-anchors.bin` or `test-update-state.bin` gets fresh keys and bundles from `tools/update-bundles` before each image, unless `UPDATE_BUNDLES_KEEP=1` |
| `make check-serial SYSTEM=hello LOG=FILE` | container | check a serial log captured from a board against the same expect file, by qemu-test's rules (LOG inside the workspace; for a Pi 5 log add `BOARD=rpi5b_2gb`, so the board's own expect file, `systems/rpi5b_2gb/SYSTEM.expect`, is used where there is one): from the Microkit loader's first line, or - a release image's loader prints nothing - from the line after U-Boot's go |
| `make pi-run PI_DEVICE=DEV PI_SYSTEMS="hello ipc-demo"` | host (images built in the container) | run systems on the Pi 5 over the Debug Probe, unattended (`tools/pi-run`; Podman's VM cannot see USB serial devices): for each, from U-Boot's prompt, a reset, the image sent gzip-compressed with `loady`, unzipped to 0x10000000 and checked by size and U-Boot's CRC-32, BCM2712's PM watchdog armed for `PI_WATCHDOG` (12) s only if its registers read as the bootloader reported, and read back as armed, and the firmware's framebuffer at that boot is the board facts' (or there is none: no monitor - which assumes `bdinfo` then prints no FB size, not yet seen on the board; it fails safe), then `go`; every command's echo checked before it is entered; each log followed live and checked by `check-serial`, and a system's `systems/NAME.qmp` of `wait`, `pause` and `serial` steps played as it goes - the serial steps typed through the probe to the debug UART (any other step is QEMU's alone, refused); a system's own reset reloads it; a system that asks for a run length (`test-run-length-N.bin`) runs for N s, its watchdog PD keeping the PM watchdog armed, and the run waits for the reset after it; the board left at U-Boot's prompt. A failed transfer or check stops the run and says what is true: nothing armed and whether the prompt answers, or, after a PM write, the watchdog's reset awaited and the board parked. Logs in `build/rpi5b_2gb/pi-run/DATE-TIME/`; one run at a time on the board (the lock file `PI_BOARD_LOCK` names) |
| `make pi-uboot PI_DEVICE=DEV PI_COMMANDS="bdinfo; md.l 107d20001c 3"` | host | U-Boot commands that read, at the parked board's prompt (`tools/pi-run uboot`; printable ASCII only; `--allow-write` adds `mw`, `cls` and `setcurs` for a display test; never `go`, `reset` or a boot) |
| `make pi-show PI_DEVICE=DEV SYSTEM=NAME` | host (image built in the container) | one system on the Pi 5 with no watchdog, for a person to watch (`tools/pi-run show`): it runs until they power-cycle the board; a power cycle within `PI_HOLD` (14400 s) is parked at U-Boot's prompt and the log checked, and after that the image is left running and the run says how to park the board. `PI_TYPE=1`: for a person to drive - what they type on this terminal goes to the board's debug UART, keys and all, and the image's lines are printed; Ctrl-] or Ctrl-C stops typing, leaving it running (`SYSTEM=uart-input-test` prints each key's events) |
| `python3 tools/serial-frame --log LOG --out FRAME.jpg` | host | the camera frame `nowayos-camera-test` dumped on serial in `usb-camera-test`, saved as a JPEG: each line of 48 bytes, base64 with its offset and CRC-32, taken from whichever of the two copies has it whole (a line another PD broke), then the whole frame's length, CRC-32, SOI and EOI checked; nothing written unless all check. LOG is `make pi-run`'s, `build/rpi5b_2gb/pi-run/DATE-TIME/NN-usb-camera-test.log`. Python standard library only |
| `make qemu SYSTEM=hello` | container | boot interactively (quit: Ctrl-A, then x); `VNC=1` also shows QEMU's screen on the host's `localhost:5900` (`open vnc://localhost:5900`; the password is printed, made for that run only) - for `SYSTEM=ui-interactive`, the clickable demo to click through |
| `make uboot` | container | U-Boot for the Pi 5 from the pinned release (`platforms/rpi5b_2gb-u-boot.config` on `rpi_arm64_defconfig`); reproducible |
| `make sdcard BOARD=rpi5b_2gb SYSTEM=hello` | container | the Pi 5 SD card's boot partition (pinned firmware, U-Boot, `platforms/rpi5b_2gb-config.txt`, `loader.img`, the glyph atlases' `OFL.txt`, the icons' `LICENSE-LUCIDE.txt`, `SHA256SUMS`); refuses OTP or secure-boot settings |
| `make std-crates-check` | container | standard-library crates in the PDs match `pds/std-crates.txt` Then `tools/check-backends`: no library the PDs link but `nowayos-entropy`'s defines getrandom's back end |

| `make screen-compiler-check` | container | Screen Compiler's `make contract-check` - every generated screen built against this `nowayos-ui` and drawn by this `nowayos-render-eg`, each fixture's frame matched with its approved image in screen-compiler's `contract-check/golden/` - when a screen-compiler clone sits beside this nowayos clone; a notice when not. A deliberate change to layout or drawing fails it until the images are redrawn in screen-compiler (`make bless-images`), approved by a person and committed there. Screen Compiler's `contract-check/Cargo.lock` records the graph of the NoWayOS crates it builds, checked with `--locked`: if a NoWayOS change alters that graph, it fails with 'cannot update the lock file'; in screen-compiler run `make contract-check` without `LOCKED` and commit the lock with the change (after a NoWayOS version change, update the `=0.1.0` requirements in `contract-check/Cargo.toml` first) |
| `make kani` | container | Kani's proofs (Kani 0.68.0 in the dev image): each crate in `KANI_CRATES` - `nowayos-ipc`, `nowayos-input`, `nowayos-display`, `nowayos-fault-policy`, `nowayos-time`, `nowayos-update`, `nowayos-socket`, `nowayos-seed`, `nowayos-net`, `nowayos-audio` - has its proofs in `src/proofs.rs`, that its record decoders never panic, overflow or read out of bounds for any input up to the longest record and keep their rules (and, in `nowayos-time`, that wall-clock time's interval arithmetic never overflows or panics, that an interval's earliest never goes back, and by exactly how much it and the latest move, for any drift with the stated properties - the real drift checked against them below 2^32 ns; that it never narrows follows from those amounts and rests on them and the property tests), and that the fault policy's rule never panics or overflows for any input and never answers restart once a limit is reached; in `nowayos-input`, also that the terminal decoder, given any six bytes and then the end of input, never panics or overflows, makes only the keys it sends and is left between keys; in `nowayos-update`, the manifest's and a bundle chunk's rules on their lengths, characters and offset, the trust list's rules and the update records' one encoding left to its property tests and fuzzing (a proof of them over a whole trust list needs more memory than the dev container has); in `nowayos-net`, the network queues' checks on a peer's writes: a descriptor decodes from any bytes, `DataRegion` accepts only a buffer inside the region, on a boundary and no longer than a buffer, and neither end reads or writes a descriptor when its peer's index puts more than the capacity in flight; in `nowayos-audio`, also that the lossy ring's consumer, whatever index its producer gives at each load, copies only slots inside the ring, keeps a record only inside the window the index loaded after its copy places, and passes every record either read or counted lost, and that its producer writes inside the ring; each harness's verification time is printed, logs in `build/kani/`. Then `tools/kani-mutation` runs its named mutations (`--list`; `KANI_MUTATIONS=NAME` for some, every one by default): each copies the workspace and removes one check - `Reader::read_bytes`' length check, `DataRegion::buffer`'s bounds check, `dequeue`'s in-flight check - and requires a named proof to fail on it, and fail where the missing check shows |
| `make ci` | container | the full CI (`container-ci`): secrets, lint, test, doc, demo, nostd, deny, atlases-check, sbom, fuzz, kani, then the rest above in order. Kani's crates and mutants, the fuzz targets and Miri's crates run only where a change since `CI_BASE` (`origin/main`) reaches (`CI_SCOPE=changed`, `tools/ci-scope`: through every crate that depends on what changed, `.workspace = true` dependencies included; a change to the fuzz harness's own library, `fuzz/src/`, reaches every fuzz target; a change to the toolchain, a lock file, a manifest, the Makefile, the make fragments or the container runs everything). In the container they are then cut to those with no cached verdict (`tools/ci-verdicts`): a crate or target that passed before with exactly the inputs it has now - its sources and those of the local crates it depends on, their locked packages, the workspace's manifest (its member list aside, and of `[workspace.dependencies]` only the entries the crate's closure uses), toolchain and cargo configuration, a product's NoWayOS crates it reaches, the Containerfile's tool pins (its FROM and ARG lines, so a package added to the image or Debian's archive moving on keeps every verdict) and the check's own flags - says `CACHED` and is not run again; a product's Kani mutants are kept the same way, by their crate's inputs, name and mutations file; a change to the Makefile or a make fragment reaches no verdict. Verdicts live in the target volume (`CI_VERDICTS`, `/cache/target/nowayos-verdicts`); `make forget-verdicts` deletes them. `make ci CI_SCOPE=full` runs every one and uses no verdict; `make kani`, `make fuzz`, `make pds-miri` and `make release-evidence` always do. The fuzz targets run `FUZZ_JOBS` (the container's CPUs) at a time |
| `make release-evidence` | container | the release evidence pack for the commit checked out (`tools/release-evidence`): refuses uncommitted changes or untracked files in nowayos or the screen-compiler clone beside it, runs `make ci` step by step, builds every image again (QEMU, and `EVIDENCE_PI_BOARD=rpi5b_2gb` for each system its facts serve), and writes `build/release-evidence/COMMIT/`: `INDEX.md` (the ci result, every file's sha256, the Security Checklist's Per Release items answered), `ci/summary.txt` and `ci/logs/`, `versions.txt` and `pins/`, `sbom/`, `images/` (each image's SBOM, seL4 record, description and report; `SHA256SUMS`), `grants/inventory.md` (every PD's memory, devices, interrupts, channels) and `crypto.md` (`tools/crypto-crates.txt` plus crates.io's cryptography category, in all four Cargo workspaces - a workspace `make sbom` covers but the pack does not read fails it; what only the fuzz harness or the atlas tool uses never ships). All but `ci/logs/` is the same for the same commit and dev image |

A product repo builds its own systems and PDs with `tools/make/system.mk`
(its "Product repos" header: `SYSTEM_REPO`, `SYSTEM`, `PDS_LIB_CRATES`,
`UNSAFE_ALLOWLIST`, `SYSTEM_FORWARD`): the same targets, toolchain, SDK, board
facts, grant rules and checks as NoWayOS's own. Keep those fragments naming no
product, and keep their variable names (container.mk's are used by research
spikes elsewhere too). A product runs one of NoWayOS's PDs - the timer, the
virtio console driver, the supervisor, the display PD (`display-stub`, which
shows the UI's frames on the Pi 5's HDMI), the input broker, the
USB host PD and the UART input PD (its program named
`PRODUCT-uart-input`, so the development-only rule binds it) - from a program
of its own that returns
the PD library's `init` (`pds/README.md`, "Adding a PD"),
and the supervisor's program names the system's children (the
`nowayos-supervisor` library's documentation shows how). Keep NoWayOS's own
programs naming only NoWayOS's test PDs. A product's `make kani` and
`make fuzz` are this fragment's too: `KANI_CRATES` and
`KANI_MUTATIONS_FILE` name its proofs and mutants, and its fuzz targets live
in a `fuzz/` workspace of its own - its own lock, a `fuzz/deny.toml` allowing
libFuzzer's licence, `libfuzzer-sys` banned in its other `deny.toml` files
 - which `make fuzz` runs with NoWayOS's own run (`fuzz-run`). With
`CI_SCOPE=changed` both keep only what a change reaches (`tools/ci-scope
--root`): the product's workspace members are its crates, and a new
`nowayos.rev` reaches everything, and the cached verdicts then keep only
those whose NoWayOS crates changed. Kani proves every crate it must in one
pool of `KANI_JOBS` harnesses (one per `KANI_JOB_GIB`, 10 GiB, of the
container's memory, less one), recording each crate's verdict only
if the pool passed, with the mutants beside it. A verdict under an earlier
key scheme for exactly today's inputs is carried over, not re-run.

Every target starts the container itself from the host. The everyday ones (fmt,
lint, test, doc, clean) run on the host instead with `IN=host`, adding
`CARGO="cargo +stable"` where the host's stable toolchain is 1.93.1.
`NOWAYOS_UPDATE_SNAPSHOTS=1 make test` rewrites golden images; review them before
anything is committed. A change to layout or drawing may also alter Screen Compiler's
approved images (`make screen-compiler-check` shows which): redraw them with `make
bless-images` in screen-compiler, where a person approves them before they are committed
(in screen-compiler); push the two repos' commits together.
